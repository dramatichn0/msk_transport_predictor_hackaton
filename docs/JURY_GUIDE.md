# Инструкция по работе с системой

Документ описывает полный рабочий сценарий: запуск системы, подачу телеметрии,
просмотр прогнозов и алертов, а также контроль основных метрик.

## 1. Запуск системы

В корне проекта выполните:

```powershell
docker compose up -d --build
```

Проверьте состояние сервисов:

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8001/health
```

Откройте программу: `http://localhost:8000/`.

## 2. Исторический датасет

Для демонстрации потока через тот же pipeline, что используется realtime,
запустите replay подготовленного split:

```powershell
Invoke-RestMethod -Method Post http://localhost:8000/api/replay/test
```

Или validation-сценарий:

```powershell
Invoke-RestMethod -Method Post http://localhost:8000/api/replay/validate
```

Используемые файлы:

| Split | Телеметрия | Расписание |
|---|---|---|
| `test` | `dataset/test/traffic.csv` | `dataset/test/schedule.csv` |
| `validate` | `dataset/validate/traffic.csv` | `dataset/validate/schedule_plan.csv` |
| `train` | `dataset/train/traffic.csv` | `dataset/train/schedule.csv` |

Replay сортирует события по времени, загружает расписание выбранного набора и
обрабатывает пакеты блоками. Ответ показывает число принятых, отклонённых и
пропущенных записей.

## 3. NDTP-эмулятор

Backend принимает поток на TCP-порту `9201`. Эмулятор направляет на него
совместимые NPL/NPH-кадры с навигационной ячейкой `G6CellNav00`.

Пример назначения в конфигурации эмулятора:

```json
{
  "targetHost": "host.docker.internal",
  "targetPort": 9201,
  "units": [
    {
      "unitId": 664030,
      "intervalMs": 5000,
      "autoGenerate": true,
      "cells": []
    }
  ]
}
```

Реализованный обработчик проверяет framing и CRC, декодирует координаты,
скорость, курс и GPS validity. `unitId`, известный расписанию, позволяет
отобразить ТС как scheduled и включить его в прогнозирование; остальные
устройства могут отображаться как контекст.

## 4. Где увидеть прогнозы и алерты

Откройте `http://localhost:8000/`. На экране доступны карта маршрутов,
положения ТС, риск по цвету, карточки транспорта, история инцидентов и
сводные показатели. Нажатие на инцидент перемещает карту к позиции события.
What-if позволяет показать сценарий изменения интервала при дополнительном
выпуске машин.

Главный экран объединяет карту, списки объектов и оперативные показатели в одном рабочем пространстве.

Карта показывает официальные маршруты и текущие позиции транспорта. Цветовая индикация помогает быстро оценить состояние движения и перейти к интересующему участку.

![Карта дашборда с маршрутами и текущими транспортными средствами](screenshots/map.png)

Панель «Состояние потока» содержит сводные счётчики обработки телеметрии, прогнозов и выявленных событий.

История инцидентов используется для просмотра предупреждений, прогноза отклонения и уровня риска. Выбор записи связывает событие с объектом на карте.

## 5. Метрики

Получить полное состояние через API:

```powershell
Invoke-RestMethod http://localhost:8000/api/state
```

В ответе `vehicles` содержит последние состояния ТС, `incidents` — историю
предупреждений, `metrics` — счётчики обработки. Среди них число пакетов,
прогнозов, неизвестных ТС, fallback ML и инцидентов. Online MAE обновляется
после того, как становятся известны фактические прибытия.

## 6. Завершить демонстрацию

Завершение демонстрации производится путём ввода команды:

```powershell
docker compose down
```
