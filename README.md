# Предиктор изменений в графике наземного транспорта

![Главный экран продукта: карта маршрутов, транспорт и оперативные показатели](docs/screenshots/main_white.png)

Хакатонный продукт для оперативной обработки телеметрии, прогнозирования
отклонения от расписания на горизонте 10–15 минут и поддержки диспетчерских
решений. Система помогает диспетчеру заранее увидеть проблемный участок,
оценить риск для маршрута и принять решение на основе единой картины движения.

Продукт объединяет потоковые данные, официальное расписание, ML-прогноз и
интерактивный BI-дашборд в одном запускаемом Docker-контуре. На карте видны
маршруты и транспорт, а боковые панели показывают состояние потока, прогнозы,
инциденты и показатели качества.

**Рабочая система и исходный код:** [GitHub-репозиторий проекта](https://github.com/dramatichn0/msk_transport_predictor_hackaton).

## Возможности продукта

- приём HTTP-телеметрии и NDTP-потока;
- отображение текущей скорости транспорта в карточках, на карте и в инцидентах;
- map matching к официальному расписанию;
- прогноз отклонения и отдельная оценка риска;
- карта маршрутов и текущих позиций транспорта;
- история инцидентов с объясняющими паттернами;
- метрики обработки и online MAE;
- What-if сценарий дополнительного выпуска транспорта;
- Docker Compose, REST API и Swagger/OpenAPI.

## Актуальное состояние версии

По сравнению с ранней версией проект расширен полноценным потоковым контуром:
добавлены map matching с учётом времени, направления и скорости, прогноз
отклонения и отдельный риск-скоринг, история инцидентов с рекомендациями,
online MAE, fallback ML, What-if-сценарий выпуска транспорта, NDTP TCP listener
с разбором NPL/NPH/CRC и поддержка светлой/тёмной темы. В последней итерации
скорость ТС также выводится в карточках, popup на карте и карточках инцидентов.

По сохранённой проверке pipeline обработал 103 018 событий validate replay и
сформировал 60 334 прогноза; на holdout получены MAE 105,37 секунды, AUC
0,7938 и Brier score 0,2045. Подробнее: [производительность и возможности](docs/PERFORMANCE_AND_FEATURES.md).

> Важно: скриншоты в `docs/screenshots/` относятся к предыдущему состоянию
> интерфейса и не отражают последнюю версию продукта. Актуальный интерфейс
> следует смотреть после запуска системы.

## Три модуля

| Модуль | Назначение | Технологии |
|---|---|---|
| ML-ядро | признаки, обучение и инференс | Python, FastAPI, NumPy, scikit-learn, LightGBM, CatBoost, PyTorch, ONNX Runtime |
| Backend | поток, расписание, прогнозы, состояние и алерты | Python, FastAPI, Pydantic, HTTPX, asyncio |
| BI-дашборд | карта, транспорт, риски и показатели | HTML, CSS, JavaScript, MapLibre GL JS, GeoJSON |

## Запуск

Из корня проекта:

```powershell
docker compose up -d --build
```

Сервисы:

- дашборд и Backend: `http://localhost:8000/`;
- Backend Swagger: `http://localhost:8000/docs`;
- ML Swagger: `http://localhost:8001/docs`;
- NDTP TCP listener: `localhost:9201`.

Проверить готовность:

```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod http://localhost:8001/health
```

Остановить:

```powershell
docker compose down
```

## Данные и демонстрация

Исходный датасет проекта доступен по ссылке:
[Яндекс Диск — датасет проекта](https://disk.yandex.ru/d/CA6tsj4aJJ4Aaw).

Для демонстрации используются расписание, поток телеметрии и обученный
модельный артефакт. Исторический поток подаётся через
`POST /api/replay/{split}`, а realtime — через TCP `9201` или
`POST /api/telemetry`.

Главный результат работы системы открывается в дашборде: цвет маршрута и ТС
показывает риск, карточки содержат прогноз, а история инцидентов помогает
диспетчеру быстро перейти к проблемному участку.
